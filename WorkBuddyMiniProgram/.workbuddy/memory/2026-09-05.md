### Key gotcha (reusable)
The Edit/Write tool converts a literal `\n` in the parameter into a real newline in the file, which breaks JS string literals. To embed a backslash-n escape inside source via tool edits, the harness preserved `\\n` (typed as `\\n` in the new_string) as a proper `\n` escape — but this was inconsistent (a separate `replace_all` turned `\n` into a real newline). Safe pattern: fix multi-line strings with a Python script writing `'\\n'` (backslash-n) to the file, never a bare `\n`. Apostrophes `\'` were preserved correctly.

## Follow-up round (same day) — second screenshot showed issues still present

Root causes that the earlier fixes missed:

1. **Engine still never ready** — `require.async` for subpackages was *hanging* on the real device (no resolve, no reject), so the fallback to `wx.loadSubpackage` never triggered. Fixed `miniapp/app.js`: reversed priority — `wx.loadSubpackage` is now primary with an 8s timeout; `require.async` is only a fallback. Promises are settled exactly once (`settleOnce`) to avoid double resolve/reject from the timeout + success race.

2. **Header still overlaps status bar** — my `_statusBarHeight` capture existed but I forgot to actually *use* it in `_initTheme` (the `if (this._statusBarHeight)` guard silently skipped when undefined). Now it appends `padding-top:<h>px` to `themeStyle`. 3. **Language picker shows raw keys** — the original 4 tables (`zh-CN/zh-TW/en/ja`) were missing `settings.language.fr/es/pt/ko/hi`. The i18n fallback chain (`current → zh-CN → key`) returned the key string when nothing had it. Fixed with a Python script that inserted all 5 missing keys into each of the 4 tables (values use the native name for each language, not translated).

4. **Privacy footer two lines** — confirmed working (has `\n`, renders two lines under `white-space: pre-line`).

### Gotcha for next time
When using `wx.getMenuButtonBoundingClientRect()` in `onLoad`, check that `rect.left` is truthy — the API can return a zero-shape object on dev tools where the capsule doesn't exist, and `screenWidth - 0 + 8` would give a huge right padding. Always gate on `rect && rect.left`.

## Third round (same day) — "拼音库加载失败，请重启小程序重试"

User reported the convert button stays gray with "拼音库加载失败，请重启小程序重试" — i.e. the FAILURE path now fires fast instead of hanging.

**Root cause:** `miniapp/app.js` `loadAll()` iterated `pkg.files` and called `_loadOne(pkg, f)` **per file**, so `wx.loadSubpackage({ name: 'data' })` fired twice concurrently (once for `pinyin.js`, once for `zdic.js`); `fontA` fired twice too. WeChat's second concurrent `loadSubpackage` for the same package name never resolves/rejects → 8s timeout → `Promise.all` rejects → `onLaunch` `.then(_, err)` sets `globalData.loadError` → gray button + failure toast.

**Fix:** Added per-subpackage dedup in `miniapp/app.js`:
- New `subpackagePromises` cache + `_ensureSubpackage(pkgName)` → `wx.loadSubpackage` is invoked **exactly once per package name**; subsequent files in the same package reuse the resolved Promise.
- Rewrote `_loadOne` to `await _ensureSubpackage(pkg.name)` then `require(reqPath)` (prefers sync require once package is ready; `require.async` only as a fallback if sync throws).
- Timeout raised 8s → 10s; header comment updated.

**Verification:**
- `node -c miniapp/app.js` → SYNTAX_OK.
- Sandbox test (real app.js, stubbed `wx`/`require`): loadSubpackage call counts = `{"data":1,"phrase":1,"fontA":1,"fontB":1}` (each package once); `globalData.ready=true`, `loadError=null`, engine set, `wordCount=2` → RESULT_OK.
- Re-ran i18n picker smoke test (9 langs × 9 options): no raw keys; `footer.privacy` has `\n` in all → I18N_OK.

**Key reusable lesson:** In WeChat Mini Programs, never call `wx.loadSubpackage({ name: X })` more than once for the same package — dedup concurrent requests behind a single cached Promise.

## Fourth round (same day) — "拼音库加载失败，请重启小程序重试" PERSISTED

The dedup fix from round 3 made `wx.loadSubpackage` behave, but the failure still persisted: the button stayed gray with the same error. Real failure mode on the device was the **synchronous `require(reqPath)` inside `_loadOne` throwing immediately** (subpackage success callback fires, then `require` throws synchronously), so the dedup Promise resolved but the per-file `require` rejected → `Promise.all` rejected → `loadError` set.

**Real root cause:** `miniapp/app.js _loadOne` used a **dynamic `require` path** built by string concatenation:
```js
var reqPath = './' + pkgRoot + '/' + rel;
loadedModules[key] = require(reqPath);   // 动态拼接
```
WeChat's bundler (especially with `lazyCodeLoading: "requiredComponents"` in `app.json`) cannot statically resolve a runtime-concatenated `require` of a subpackage module — the module record is not emitted into the subpackage bundle in a way that `require` can look up by dynamic string. Result: `require` throws "module not found", `loadAll()` rejects, button grays forever.

**Fix in `miniapp/app.js`:**
1. Added `_requireLiteral(key)` — a `switch` returning a **static/literal `require`** for each known subpackage key (6 files: pinyin/zdic/phrase/font-part1/2/3). Bundler now sees literal requires and correctly emits module records into the proper subpackages.
2. `_loadOne` now calls `_requireLiteral(key)`; `require.async` fallback kept for old base libraries.
3. Extracted `_startLoad(app)` from `onLaunch` so the flow is reusable.
4. Added `App.reload(cb)` — clears `subpackagePromises` and `loadedModules`, re-runs `_startLoad`, and fires `readyCallbacks` on settlement. Pages can retry loading without restarting the mini program.

**UX improvements so users don't get stuck again:**
- `miniapp/pages/index/index.js`: new `loadFailed` flag. `_onReady` now shows the real `loadError.message` in the status bar (was just a generic "请重启小程序重试"). Added `onRetry` that calls `app.reload(_onReady)`.
- `miniapp/pages/index/index.wxml`: when `loadFailed`, the "转换" button is replaced by "重试加载" (calls `onRetry`).

**Verification:**
- `node -c miniapp/app.js` and `node -c miniapp/pages/index/index.js` → SYNTAX_OK.
- Full simulation (stubbed `wx`/`App`/`getApp`): `globalData.ready=true`, `loadError=null`, `wordCount=52990`, `engine` initialized, `engine.convert('中国银行')` → `中(zhōng)国(guó)银(yín)行(háng)`. RESULT_OK.

**Reusable lesson (CRITICAL):** In WeChat Mini Programs, **subpackage modules must always be `require`-ed via a literal/string-constant path**, never via runtime concatenation (`'./' + a + '/' + b`). With `lazyCodeLoading` enabled, the bundler won't emit a discoverable module record for dynamic requires, and runtime `require` will throw. Use a `switch`/`map` to dispatch on a known key to a literal `require()` call.
